Livter — Minimal Debug Report
================================

مبنای اصلاح: Game.zip ارسالی کاربر
روش: فقط رفع ناسازگاری‌ها و خطاهای مسیر اجرای فعلی؛ منطق تولید جهان و الگوریتم‌ها عمداً بازطراحی نشده‌اند.

فایل‌های تغییرکرده (۸ فایل):
1) main.py
   - ترتیب راه‌اندازی اصلاح شد: SDL ابتدا ساخته می‌شود، سپس ابعاد دریافت می‌شوند و بعد ماژول‌هایی که WIDTH/HEIGHT را import می‌کنند بارگذاری می‌شوند.
   - import کنترلر که در نسخه اصلی کامنت بود اصلاح شد.
   - World بدون display ساخته می‌شود و حلقه بازی نتیجه رویداد SDL را از World.update دریافت می‌کند.
   - تعریف تکراری و ناسازگار EntityData حذف شد؛ تعریف هم‌تراز با C++ از cppfuncs استفاده می‌شود.

2) cppfuncs.py
   - GetWindowsize مطابق cmain.cpp سه آرگومان می‌گیرد.
   - restype تابع drawobj برابر bool شد.
   - restype تابع keycont که در C++ خروجی void دارد اصلاح شد.
   - helper دریافت اندازه پنجره آرگومان سوم null را ارسال می‌کند.

3) world.py
   - world.update ابتدا SDL events را poll می‌کند و بعد ورودی کنترلر را می‌خواند؛ ترتیب برای pressed_this_frame لازم است.
   - world.draw دیگر pygame را صدا نمی‌زند: زمین از pr، اشیا و NPCها از drawobj و پایان فریم از present استفاده می‌کنند.
   - امضای سازنده و فراخوانی BlocksWorld.create هماهنگ شدند.
   - ابعاد پنجره در تغییر اندازه به Camera و ماژول‌های مرتبط منتقل می‌شوند.

4) BlockManager.py
   - drawBlocks داده‌های موجود Chunk را به آرایه‌های int32 و مختصات Chunk تبدیل می‌کند و به تابع C++ pr می‌دهد.
   - getblock با ساختار واقعی Chunk.blocks یعنی کلیدهای (local_x, local_y) هماهنگ شد.
   - هیچ‌یک از توابع noise، get_visible_chunks، faketoreal، getAlgoritm یا move بازنویسی نشدند.

5) worldchunk.py
   - خروجی نام بلوک از determine_block_type حفظ می‌شود؛ قبلاً مقدار دوم (صفر) به‌اشتباه به‌عنوان texture جست‌وجو می‌شد.

6) texture.py
   - Texture.init اکنون شناسه‌ها را روی کلاس Texture ذخیره می‌کند، نه متغیرهای محلی.
   - مسیر تصاویر نسبت به پوشه خود فایل ساخته می‌شود.
   - یک texture شفاف با شناسه 0 رزرو می‌شود، چون Pr در C++ شناسه صفر را خانه خالی در نظر می‌گیرد.

7) contoroler.py
   - x و y به خروجی فعلی کنترلر اضافه شدند تا با NPC.getAPI سازگار باشد؛ فیلدهای قبلی حذف نشدند.

8) npc.py
   - activate برای نگهداری اشاره‌گر buffer که main درخواست می‌کرد اضافه شد.
   - دستور منفی E دیگر به‌اشتباه تخته جدید نمی‌سازد؛ مسیر remove موجود object فراخوانی می‌شود.
   - کنترلر قدیمی NPC در صورت نبود ورودی، API سکون برمی‌گرداند.

مواردی که عمداً دست‌نخورده ماندند:
- الگوریتم OpenSimplex و آستانه‌های زمین/رودخانه
- اندازه Chunk و ساختار RealChunks/Chunks و محدوده margin_chunks
- الگوریتم mirror و ساختار faketoreal (بدنه کپی بلوک‌ها در نسخه اصلی کامنت شده بود؛ برای جلوگیری از تغییر منطق فعال‌سازی نشد)
- سرعت و فرمول حرکت دوربین
- cmain.cpp و فایل‌های DLL؛ APIهای موجود آن‌ها استفاده شده‌اند و تابع C++ جدیدی اضافه نشده است.
- سیستم‌های HUD، inventory و event قدیمی که در حلقه فعلی World استفاده نمی‌شوند.

نکات و محدودیت‌های مهم:
- در cmain.cpp فعلی، آرایه EntityData فقط با CreateEntities تخصیص داده و در Quit آزاد می‌شود؛ تابعی برای رندر مستقیم این آرایه وجود ندارد. رندر فعلی از pr و drawobj انجام می‌شود. NPC.activate فقط pointer buffer را نگه می‌دارد و ادعای sync کردن Entityها به C++ نمی‌کند.
- پوشه assets در Game.zip ارسالی وجود نداشت. کد مسیر assets کنار main.py را می‌خواند؛ برای نمایش تکسچرهای تصویری باید همان پوشه را در پروژه قرار دهی. در صورت نبود تصاویر، LoadImageTexture مقدار خطا می‌دهد و هشدار چاپ می‌شود.

آزمون‌ها:
- Syntax compile برای تمام فایل‌های .py: موفق
- آزمون یکپارچه با mock برای مرزهای SDL/C++: موفق؛ render، pr، drawobj و present فراخوانی شدند.
- در آزمون mock، 25 Chunk به Pr ارسال شدند و مسیر ساخت/برداشتن تخته بررسی شد.
- اندازه و offsetهای EntityData در ctypes با struct موجود در cmain.cpp برابر است: 52 بایت.
- اجرای واقعی cppmain.dll روی ویندوز در این محیط انجام نشد؛ بنابراین runtime روی دستگاه کاربر هنوز تأیید نشده است.
